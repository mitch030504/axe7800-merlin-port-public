# Cells verified on 2026-10-14 (recorded before the scratchpad was lost to a shutdown)

Raw intermediate files (retail volume copies, decompressed kernels) lived in a tmpfs scratchpad
and were lost when the PC shut down. The commands are logged in `router-commands.txt`; the
results are recorded here verbatim and can be regenerated by re-running them.

## S1 — upload resources
- Router: `MemAvailable` 267,116 kB, `MemTotal` 508,152 kB; `/var` tmpfs 254,076 kB (324 kB used),
  `/tmp/mnt` tmpfs 254,076 kB.
- Stock `httpd/web.c` `do_upgrade_post`, `RTCONFIG_HND_ROUTER_AX_6756` branch: `upgrade_rc("stop")`,
  then `inc_uploadImg(stream, &len, &imageLen)` streams the upload into flash. There is no
  full-image RAM staging and no explicit size cap.

## S3/S4 — commit vs boot-once (corrects "no automatic fallback")
- `web.c`: `boot_set = BOOT_SET_NEW_IMAGE_ONCE` (unless `sec_upgrade` or ATE mode), then `setBootImageState(boot_set)`.
- `bcm_flashutil.c` `setBootImageState()`, metadata (non-legacy) layout: `PARTn_IMAGE_ONCE`
  keeps the *other* (old) image committed and calls `setBootReason(BCM_BOOT_REASON_ACTIVATE)`.
- `u-boot board_tpl.c`: the boot reason is read only when the reset status has `SW_RESET_STATUS`.
  If both slots are valid and `ACTIVATE` (0x1) is set, it selects `3 - committed`. It then
  immediately writes `(reason<<16) | BCM_BOOT_REASON_WATCHDOG(0x4) | BCM_BOOT_PHASE_UBOOT(0x10)`,
  so bit 0 is clear on the next boot (one-shot). A power-on reset leaves `last_reset_reason = 0`
  and boots the committed image. (The `TODO` comment above that code is stale; the logic below it
  implements the fallback.)
- `rc/init.c` `sync_boot_state()`: if the booted partition differs from the reboot partition, it
  calls `setBootImageState(BOOT_SET_NEW_IMAGE)` (commit). It is called after `start_misc_services()`
  under `RTCONFIG_HND_ROUTER_AX_6756`. In Merlin the function body, the reboot-partition helper and
  the call site are **identical** to stock's.
- Consequence: a Merlin failure **before** `sync_boot_state()` falls back to stock on the next
  reboot or power cycle. After it, Merlin is committed.

## S4 — loader on the router
- `/dev/mtd1` (2,097,152 B, read-only): `U-Boot TPL 2019.07 (Dec 15 2022 - 10:28:29 +0800)`, `U-Boot SPL
  2019.07 (Dec 15 2022 - 10:28:31 +0800)`, with `RESET STATUS is 0x%x`, `BOOT REASON is 0x%x`,
  `SELECTED Image %d FIT_VOL_ID is %d`, `metadata copy %d crc bad`. This same loader boots the
  25206-generation U-Boot in retail `bootfs2` today.

## S5 — ATF
- The armtf source trees in the GPL and Merlin are identical (0 entries differ). The byte-difference
  count tracks the git-describe version-string length: retail (`asuswrt_3.0.0.4.388rc1-dirty`,
  41 chars) vs stock (13): 1,902 B; retail vs Merlin (47): 1,318 B; stock vs Merlin, same sources:
  1,886 B. Not byte-proven (rebuild attempt pending).
- **Superseded on 2026-10-15:** byte-proven by a from-scratch rebuild; see
  [`session-2026-10-15-verified-cells.md`](session-2026-10-15-verified-cells.md).

## S6/S12 — U-Boot proper and rescue
- Retail `bootfs2` U-Boot vs stock build: 11 differing bytes; vs Merlin `v12e`: 12. All lie inside
  the build banner `U-Boot 2019.07 (...)` at offset 893550 (+46). U-Boot proper, including ASUS
  rescue (`asus_rescue`, TFTP on 192.168.1.1), is otherwise byte-identical to retail.
- No FIT signature nodes in retail, stock or Merlin, and no `/signature` node in any U-Boot DTB.
  `secboot=1` in the env, but the router boots an unsigned hash-only bootfs today.

## S7 — kernel
- LZO-compressed `kernel` subimage; decompressed `Image`: retail 11,761,976 B = stock 11,761,976 B;
  Merlin 11,761,836 B.
- Strings (paths normalised): retail vs stock differ in 8 lines (banner and three initramfs cpio
  mtimes). Stock vs Merlin (strings of 10+ chars): stock-only = PPP deflate (module in Merlin), PPP
  multilink (disabled in Merlin), `brcmnand` corrected/uncorrectable error messages (Merlin
  `dev_dbg`), banner and initramfs. Merlin-only = banner and initramfs mtimes.
- Running config (`/proc/config.gz`) is identical to the stock GPL `.config`.
- Command line: DTB `/chosen/bootargs = "console=ttyAMA0 earlyprintk debug irqaffinity=0
  pci=pcie_bus_safe isolcpus=3 rootwait"` (identical DTB); U-Boot appends `mtdparts`, `root`,
  `ubi.*`; `CONFIG_CMDLINE` is identical in retail and Merlin and not forced.

## S9 — NVRAM encryption, login, erase/format
- `enc_nvram`, `dec_nvram`, `pw_enc`, `pw_dec`, `pw_enc_blen`, `pw_dec_len` and `set_enc_nvram`
  are defined only in the 25206 `shared/prebuild/spwenc.o`, which Merlin links unchanged.
  `enc_str`/`dec_str` (`shared/shutils.c`) are identical to stock. Both `httpd` builds read
  `http_passwd` via 3× `nvram_safe_get("http_passwd")`.
- The erase/format/reset call sites in `rc`+`shared` are the same set in stock and Merlin (Merlin
  lacks the `hnd_nvram_erase` applet). `rc/ubifs.c` (this model's JFFS path) is identical apart from
  creating `/jffs/{scripts,configs,addons}`; formatting happens when the volume is missing (CORRECTED 2026-10-15: also when the first UBIFS mount fails, see owner-trigger-check-2026-10-15.md)
  or `ubifs_format=1`.
